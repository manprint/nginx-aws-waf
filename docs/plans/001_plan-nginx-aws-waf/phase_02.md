**R2 facts that bind the generated text:**
1. Chain continuation lines start at column 0.
2. Every chained link has an action string (at least `"t:none"`).
3. `setvar` marking a hit goes on the LAST link.
4. Never `setvar` an empty value.
5. Quote setvar with macros: `setvar:'tx.a=%{tx.b}'`.
6. Operators containing `"` are escaped as `\"`.

### ID map (refines D23)
| Item | ID |
|------|----|
| catalog rule detectors | `B+0..B+6` |
| label | `B+7` |
| terminate | `B+8` |
| aws-default | `B+9` |
| group skip | `BaseID(g)+1` (e.g. 1200001) |
| custom rule N | `1500000 + siteIdx*1000 + ruleIdx*10`; condition helpers `N+1..N+6` (max 6 conditions); terminate `N+8` |
| scope-down SD | `1600000 + siteIdx*100 + groupIdx*10`; reset `SD`, helpers `SD+1..SD+6`, set `SD+7` |
| path override i | `1700000 + siteIdx*100 + i` (i < 100) |
| engine | 1900001 (defaults), 1900002 (per-request init), 1900003 (raw_path), 1900004 (geo), 1900010+groupIdx (group defaults) |
| site vars | `1910000 + siteIdx*10 + k` (k = 0 base, 1 groups, 2 actions) |
| evaluator | 1900800, 1900801, 1900900, 1900910–1900913, 1900920, 1900930 |

siteIdx = index in the sorted site_id list. groupIdx = catalog index (iprep 0, anonip 1, crs 2, kbi 3, sqli 4). ruleIdx = index in the effective custom-rule list. GeoBlock (when configured) is ruleIdx 0, followed by the other rules.

```
# site <site_id> idx <siteIdx>

SecRule TX:raw_path "@beginsWith <prefix>" "id:<1700000+i*100+j>,phase:2,pass,nolog,setvar:tx.act_<id>=<a>,..."   # one per path override
```
**Ordering fact (R2, re-probed):** within each phase, site-file rules run BEFORE main.conf rules. So:
- line 1 (identity) is phase 1, which suppresses the conditional main 1900001;
- lines +1, +2 and the path overrides are phase 2, so they run after the unconditional main phase-1 defaults (1900010+gi) and before the first group.

Never move them to phase 1. Test T-R12 (1.4 e2e, `count-override`) catches a regression.
Effective rule action = the `rule_action_overrides` value if set, else the catalog default. If the group's `override_action` is `count`, then block/allow become count. A group is active when it is non-optional and not `enabled: false`, or optional with `enabled: true`.

### Custom rule (site S, id N, action A, conditions c1..cn, n ≤ 6)
For each condition i (helper):
```
SecRule TX:site "@streq S" "id:<N+i>,phase:2,pass,nolog,chain"
SecRule <VAR_i> "<OP_i>" "t:none<,t:x…>,setvar:tx.c<N>_<i>=1"
```
Main rule:
```
SecRule TX:site "@streq S" "id:N,phase:2,pass,nolog,auditlog,msg:'AWSWAF N',tag:'awswaf-rule:custom:S/<Name>',logdata:'a=<A>;tb=%{tx.term};ab=%{tx.awsterm};sc=1;v=;x=',chain"
SecRule TX:term "@eq 0" "t:none,chain"
SecRule TX:c<N>_1 "@eq 1" "t:none,chain"          # negated condition: SecRule &TX:c<N>_1 "@eq 0" "t:none,chain"
…
SecRule TX:c<N>_n "@eq 1" "t:none,setvar:tx.hit_N=1"
```
If A ≠ count:
```
SecRule TX:hit_N "@eq 1" "id:<N+8>,phase:2,pass,nolog,chain"
SecRule TX:term "@eq 0" "t:none,setvar:tx.term=N,setvar:tx.term_action=A"
```

Condition → (VAR, OP):
| Condition | VAR | OP |
|-----------|-----|----|
| `label L` | `TX:lbl_<B>` (B = RuleByLabel) | `@eq 1` |
| `label_namespace` | `TX:ns_<groupkey>` | `@eq 1` |
| `uri_path` | `TX:raw_path` | exact→`@streq v`, starts_with→`@beginsWith v`, contains→`@contains v`, regex→`@rx v` |
| `header{name}` | `REQUEST_HEADERS:<name>` | same as uri_path |
| `query_arg{name}` | `ARGS_GET:<name>` | same as uri_path |
| `method [M…]` | `REQUEST_METHOD` | `@rx ^(?:M1|M2)$` |
| `ip_set [c…]` | `REMOTE_ADDR` | `@ipMatch c1,c2` |
| `geo [CC…]` | `TX:geo_cc` | `@rx ^(?:IT|FR)$` |
| `size` | body→`REQUEST_BODY`, query_string→`QUERY_STRING`, uri_path→`TX:raw_path`, cookie→`REQUEST_HEADERS:Cookie`, header:X→`REQUEST_HEADERS:X`; always add `t:length` | gt→`@gt v`, ge→`@ge`, lt→`@lt`, le→`@le`, eq→`@eq` |

Transforms from `transform:` are appended after `t:none`, before `setvar`. Values are inserted as is, with `"` escaped to `\"`. Validation (0.5 + rule added here) rejects newlines and the characters `'` and `"` in uri_path/header/query_arg values, except in `regex`.

### Scope-down (site S, group g, SD)
- Helpers `SD+i` are like custom helpers, but set `tx.sd<SD>_<i>=1`.
- Reset rule:
  ```
  SecRule TX:site "@streq S" "id:SD,phase:2,pass,nolog,setvar:tx.inscope_<k>=0"
  ```
- Set rule:
  ```
  SecRule TX:site "@streq S" "id:<SD+7>,phase:2,pass,nolog,chain"
  SecRule TX:sd<SD>_1 "@eq 1" "t:none,chain"        # negated: &TX:sd<SD>_1 "@eq 0"
  …
  SecRule TX:sd<SD>_n "@eq 1" "t:none,setvar:tx.inscope_<k>=1"
  ```
- Order: helpers, then reset, then set.
